# Raff-SEO-GEO audit checklist

This checklist is conditional: use only checks relevant to the site and request. The links point to primary sources; recheck current guidance when a rule may have changed. If data or access is unavailable, report that limit instead of inferring that the feature or result is absent.

## Access and indexing

1. On important pages, check HTTP status, redirects, intended canonical version, access without signing in, `noindex`/`nosnippet` directives, `robots.txt`, and any CDN blocks. `robots.txt` controls crawling, not privacy or deindexing by itself; a crawler must be able to read `noindex`: [Google](https://developers.google.com/search/docs/crawling-indexing/robots/intro), [Bing](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a).
2. Compare served HTML, browser rendering, and, if available, rendering inspected in the search engine's tool, especially for JavaScript applications. Check that essential content is accessible and readable as text; do not infer search-engine rendering from code alone: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Google AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).
3. Check HTML internal links to important pages, navigation, duplicates, and canonical/redirect consistency. A canonical is a signal, not an absolute instruction: [Google](https://developers.google.com/search/docs/crawling-indexing/canonicalization), [Bing](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a).
4. If meaningful URLs need discovery, check the sitemap: canonical, indexable URLs; availability; `lastmod` reflecting a real change; and reference in `robots.txt` or submission through the engine's tool. A sitemap aids discovery without guaranteeing indexing: [Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Bing](https://blogs.bing.com/webmaster/July-2025/Keeping-Content-Discoverable-with-Sitemaps-in-AI-Powered-Search).

## Content and presentation

5. For each page, examine the reader's need, useful answer, accuracy, first-hand experience or site-specific evidence, date when relevant, explanatory links, and duplicate content. If available, use queries and pages in Search Console or Bing Webmaster Tools to identify needs without inventing search volumes. Avoid mass-produced pages that target minor query variants; structure content for readers, without a mandatory word count or “AI” format: [Google AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [Search Console](https://developers.google.com/search/docs/monitor-debug/search-console-start).
6. Check distinct, descriptive page titles; useful descriptions; clear sections; and relevant images with suitable alt text. Compare mobile and desktop: essential content, titles, metadata, indexing directives, and structured data should remain equivalent when the versions differ. `og:image` may help Google choose a preview image, but is not evidence of a ranking effect: [Google SEO guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [mobile indexing](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing), [Google Images](https://developers.google.com/search/docs/appearance/google-images).
7. If equivalent pages exist for multiple languages or regions, check `hreflang` annotations, their URLs, and return links; do not add them to a single-language site without variants: [Google](https://developers.google.com/search/docs/specialty/international/localized-versions).
8. Check real user experience (readability, mobile navigation, latency, stability, and accessibility) with available tools and data; do not turn a laboratory score into observed traffic or citations: [Google page experience](https://developers.google.com/search/docs/appearance/page-experience).

## Enhancements and AI search engines

9. Consider structured data only for a currently documented use, with truthful properties appropriate to the page. For a rich result, check required properties, matching visible content, quality rules, and syntax with the Rich Results Test when it supports the type. Other documented uses, such as `Organization` for identity clarity or `primaryImageOfPage` to suggest an image, are not promises of a rich result or ranking: [Google gallery](https://developers.google.com/search/docs/appearance/structured-data/search-gallery), [policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), [Organization](https://developers.google.com/search/docs/appearance/structured-data/organization), [Images](https://developers.google.com/search/docs/appearance/google-images). `FAQPage` has not been a Google rich-result tactic since May 2026: [Google update, May 8, 2026](https://developers.google.com/search/updates#faq-deprecation).
10. If ChatGPT Search is in scope, inspect `OAI-SearchBot` and any network blocks, then separately assess training choices for `GPTBot`. Do not treat `ChatGPT-User` as the indexing crawler; access does not guarantee citations: [OpenAI](https://developers.openai.com/api/docs/bots).
11. For Google AI Overviews and AI Mode, check indexing and snippet eligibility and, with owner access, the effective value of the **Search generative AI** control in Search Console, including any inherited setting from a parent property. An exclusion may prevent links and content use in these features despite an indexed page. Never change this choice without an explicit request; `Google-Extended` concerns training and is separate from this control. No special file or schema is required: [Google AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [Search Console control](https://support.google.com/webmasters/answer/16908024).
12. For Bing/Copilot, check indexing and the directives Bing supports for content shown or used in Copilot; do not transfer Google rules automatically. If the site changes frequently, consider IndexNow to notify the engine about added, updated, or deleted URLs, without promising crawling or indexing: [Bing guidelines](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a), [IndexNow](https://www.bing.com/indexnow/getstarted).
13. If the site sells products or represents a local business, check relevant Merchant Center or Google Business Profile information and, for Bing local search, Bing Places. These services are context-dependent options, not prerequisites for every site or guarantees of citation: [Google AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [Bing AI Performance](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview).

## Validation and measurement

14. After a change, run project tests, inspect HTML and rendered pages, then verify the production response after deployment if the user authorized deployment. Distinguish local validation, deployment, indexing, and appearance in an AI answer. For a review-only request, inspect a provided accessible public URL read-only; otherwise state the audit's limit.
15. With first-party data access, use URL inspection and ordinary performance reports for indexing and queries/pages. For Google's generative Search, the dedicated report measures **link impressions** in AI Overviews and AI Mode, groupable by page, country, device, or date; it does not give the position in an answer or a universal citation count, and may be unavailable without access or impressions: [Search Console](https://support.google.com/webmasters/answer/16984139).
16. For Bing, **AI Performance** (public preview) measures citations across Copilot, Bing AI summaries, and some integrations; grounding queries are sampled, and counts are neither rankings nor positions within answers: [Bing Webmaster Blog](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview). Compare relevant periods and pages without automatically attributing a change to an intervention; a `site:` query is not exhaustive proof of indexing.
